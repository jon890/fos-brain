# 하네스 회고·실행 기록·완료 task 정리

## 질문

하네스가 자기개선을 위해 만들던 원시 회고, 실행 통계와 완료 task가 실제로 다음 작업에 쓰이는지 확인했다.
또한 회피 패턴을 공용 스킬 내부가 아니라 저장소 `docs/`에서 패턴당 한 파일로 관리하는 최신 방식을 기준으로 문서 구조를 다시 판단했다.

## 관찰

- `docs/retrospectives/`와 `RUNS.md`를 의무 생성했지만 이를 조회하거나 계획 입력으로 쓰는 활성 소비자가 없었다.
- 같은 교훈이 원시 회고와 `docs/pitfalls/`에 중복됐다.
- 역할별 회고 절차는 공용 스킬과 저장소 오버레이에 반복돼 한쪽만 바뀌면 서로 어긋났다.
- 완료 task와 `ROADMAP.md`는 현재 코드·ADR보다 오래된 구현 설명과 이미 끝난 착수 순서를 남겼다.
- `codebase-maintenance`는 `harness-cleanup`, `docs-check`와 책임이 겹쳤고 고유 소비자가 없었다.

## 결정

1. 일회성 사건, 실행 횟수와 판정 통계는 PR·작업 보고와 Git 이력에만 둔다.
2. 반복 가능하고 일반화되며 검출 방법이 있는 교훈만 `docs/pitfalls/`에 패턴당 한 파일로 승격한다.
3. 원시 회고는 승격 뒤 보존하지 않는다. 기존 패턴이면 그 파일을 보강하고 별개 패턴일 때만 새 파일을 만든다.
4. 완료 task와 소비되지 않는 로드맵은 삭제한다. 미착수 task도 현재 제품 결정이 아닌 오래된 백로그라면 필요할 때 다시 planning한다.
5. 삭제된 task 번호는 Git 이력에서 찾아 재사용하지 않는다.
6. 소비자가 없고 다른 스킬과 책임이 겹치는 스킬은 제거한다.
7. 공용 `planning`, `build-with-teams`, `review-fix`는 원시 회고와 실행 기록 생성 계약을 갖지 않는다.

## 보존한 지식

삭제한 회고 중 재사용할 가치가 있던 내용은 두 패턴으로 승격했다.

- 가드를 넣으면 그 가드가 없을 때 실패하는 회귀 테스트를 함께 쓴다.
- 결정, 옵션이나 사용자 표면을 폐지하면 내부 식별자와 사용자 표현을 현재 문서 전체에서 함께 검색한다.

## 검증

- public 저장소의 문서 정적 검사와 깨진 참조 검사 통과
- ADR과 pitfalls의 실제 파일 집합과 INDEX 집합 일치
- 공용 스킬 구조 검증 통과
- 타입 검사, 전체 테스트와 CLI 명령 카탈로그 검증 통과
- 저장소와 공용 스킬을 나눈 독립 검토에서 모두 PASS
