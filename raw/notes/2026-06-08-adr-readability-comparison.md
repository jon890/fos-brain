# ADR 가독성 비교 — 같은 템플릿, 다른 가독성

같은 planning 하네스·같은 ADR 템플릿(결정 / 맥락 / 대안 기각 / 트레이드오프)을 쓰는
두 프로젝트의 `adr.md` 를 비교했다.

- **CLI 프로젝트** — 개인 CLI 도구. ADR 11개.
- **FastAPI 문서 파싱 서비스** — 운영 중인 백엔드 서비스. ADR 25개.

사용자 관찰: 후자의 ADR 가독성이 더 좋아 보인다. 그 차이의 원인을 분석했다.

## 비교 축

| 축 | CLI 프로젝트 | 문서 파싱 서비스 | 우위 |
|----|-------------|------------------|------|
| 대안 기각 포맷 | 한 줄 괄호 인라인 압축 (`Go(이유), Python(이유)`) | 옵션마다 별도 bullet (`**옵션** — 이유`) | 후자 |
| 맥락·트레이드오프 호흡 | 후기 ADR 일부 한 bullet 200자+ | 거의 모든 bullet 이 한 사실 단위 | 후자 |
| 호흡 일관성 | 초기 압축 ↔ 후기 과밀 편차 큼 | 25개가 같은 밀도·구조 | 후자 |
| 작성 원칙 주석 | 없음 (인덱스만) | 파일 상단 "결정의 무엇·왜·대안만, 구현은 코드에" + planning 링크 | 후자 |
| 근거 구체성 | 정성 서술 위주 | 운영 실측(%, 측정값, 확인 날짜) 풍부 | 후자 |
| 탐색성 | ADR Index(클릭 목차) + anchor | 구분선만, 인덱스 없음 | 전자 |

## 핵심 통찰

가독성 차이는 **템플릿이 달라서가 아니라, 같은 템플릿에 semantic line break 를 더 엄격히
적용**했기 때문이다. 결정적 두 가지:

1. 대안 기각의 항목 분리 — `옵션(이유), 옵션(이유)` 괄호 인라인은 비교가 눈으로 안 된다.
   `**옵션** — 이유` 를 줄마다 끊으면 대안 비교가 시각적으로 즉시 된다.
2. 한 bullet = 한 사실 — 200자 넘는 bullet 은 정보 4개가 뭉친 신호다.

탐색성은 전자가 낫다(ADR Index + anchor). 이상적 ADR 은 두 장점의 합집합이다.

## 도출 원칙

1. 대안 기각은 옵션마다 별도 bullet, 괄호 인라인 나열 금지.
2. 한 bullet = 한 사실, 200자 초과는 분리.
3. 모든 ADR 이 같은 호흡 — 초기 압축 / 후기 과밀 편차 회피.
4. 파일 상단에 작성 원칙 1줄 + planning ADR 점검 링크.
5. 근거는 실측 수치로.
6. 탐색성 — ADR Index(클릭 목차) + anchor 병행.
