## 핵심 정리

### Codex는 코딩 도구를 넘어 업무 에이전트로 쓰인다

인터뷰에서 OpenAI 스타트업팀은 Codex를 코드 작성만이 아니라 데이터 분석, 고객 피드백 요약, 리서치, 반복 업무 자동화에 사용한다고 설명한다.
예시로는 국가별 스타트업 사용 데이터 분석, 알파 모델 피드백 요약, Slack 스레드 탐색, Gmail·Calendar 연결, 정기 리팩터링 자동화, computer use를 통한 브라우저 조작이 나온다.

핵심은 Codex를 "IDE 안의 코드 생성기"로 좁히지 않고, 여러 시스템을 연결해 업무 흐름을 대신 수행하는 범용 작업 표면으로 쓰는 것이다.

### AI 네이티브 스타트업의 방어력은 고객 워크플로우 이해에서 나온다

OpenAI가 일반 지능과 범용 모델을 제공할수록, 스타트업은 더 깊은 고객 문제와 특정 산업 워크플로우에 집중해야 한다고 말한다.
제품이 "일반 지능" 자체에 가까우면 기반 모델 회사와 겹칠 수 있지만, 특정 고객군의 실제 업무를 끝까지 해결하는 수직 문제라면 기반 모델을 플랫폼으로 활용할 수 있다.

또한 지금 모델 한계에 맞춰 제품을 고정하기보다 6개월 뒤 모델이 가능해질 일을 전제로 제품을 설계하라는 조언이 나온다.
모델 성능이 올라오면 오래된 아키텍처와 프롬프트 체계를 버릴 수 있어야 한다는 점도 강조한다.

### AI 네이티브 조직은 더 작고 평평해질 수 있다

AI를 잘 쓰는 조직에서는 한 명의 생산성이 크게 올라가고, 작은 팀이 더 오래 작은 상태를 유지할 수 있다.
두 명의 창업자가 Codex 에이전트를 여러 명처럼 활용해 제품 개발, 고객 지원, 운영 자동화를 병행하는 사례가 언급된다.

조직적으로는 중간관리의 보고 취합 업무가 줄고, 제품·엔지니어링·디자인 경계가 흐려진다.
고객 가까이에서 평가 기준을 만들고 빠르게 고치는 forward-deployed engineer 역할이 더 중요해진다는 관찰도 나온다.

### AI 시대 인재상은 기초 체력과 팅커러 태도의 결합이다

인터뷰는 AI가 도구를 바꾸더라도 컴퓨팅, 프로그래밍 언어, 알고리즘, 수학, 글쓰기, 비판적 사고, 발표 능력 같은 기초 역량은 계속 중요하다고 본다.
동시에 새 도구를 자주 만져보고 실험하는 "passionate tinkerer" 태도가 중요하다고 강조한다.

AI 시대의 커뮤니케이션은 사람에게만 향하지 않는다.
전문가가 암묵적으로 알고 있는 요구사항을 AI에게도 명시해야 하므로, 좋은 설명력과 구조화 능력이 생산성의 핵심이 된다.

### 재귀적 자기개선은 작은 실무 루프에서 먼저 나타난다

영상 제목의 "재귀개선"은 거대한 AGI 선언이라기보다 OpenAI 내부에서 모델이 제품을 만들고, 제품이 다시 모델과 업무 방식을 개선하는 작은 루프를 가리킨다.
예를 들어 OpenAI 직원이 Codex로 Codex 관련 분석과 자동화를 하고, 모델 피드백을 더 빠르게 요약하며, 내부 도구와 대시보드를 만들어 다시 제품 개선 속도를 높이는 식이다.
