# brain-delete

brain 에서 더 이상 필요 없거나 잘못 들어온 wiki 페이지를 안전하게 떼어낸다.
brain 은 백링크·INDEX·log·Sources·cross-link 로 촘촘히 연결돼 있어, 파일만 지우면 깨진 링크와 고아 참조가 남는다.
이 스킬은 **연결을 먼저 분석하고, 미리보기·승인을 거친 뒤** 정리까지 함께 수행한다.

사용자 명시 요청 시에만 실행한다. 다른 스킬이 자동으로 호출하지 않는다.

## 대상 디렉터리

`~/personal/fos-brain` — 네임스페이스별(public·private)로 동작한다.

| 네임스페이스 | 경로 |
| --- | --- |
| public | 루트(`wiki/`) |
| private | `private/wiki/` |

대상 페이지가 어느 네임스페이스인지 먼저 확정한다. 모호하면 `AskUserQuestion` 으로 확인.

## 안전 원칙 (불변)

1. **미리보기·승인 없이 삭제 금지.** 무엇을 지우고 어떤 링크가 끊기는지 표로 보인 뒤에만 진행한다.
2. **raw 원본은 기본 보존.** wiki 페이지가 인용한 `raw/` 파일은 삭제하지 않는다(CLAUDE.md 금지사항). 사용자가 raw 까지 명시적으로 지목한 경우에만, 별도 확인 후 삭제.
3. **끊기는 백링크는 매번 확인 후 처리.** 자동 일괄 제거 금지 — 링크마다 처리 방식을 사용자에게 묻는다.
4. **사용자가 직접 수정한 흔적이 보이면** 덮어쓰기·삭제 전 확인.
5. **공개 빌드를 깨지 않는다.** public 페이지 삭제 시, 그 페이지를 가리키는 다른 public 백링크를 반드시 정리한다.

## 절차

### 0. qmd 인덱스 점검
`qmd status` 로 동기화 확인. public 파일이 어긋나면 작업 후 `qmd update && qmd embed` 로 재동기화(삭제 반영).

### 1. 대상 식별
- 사용자가 페이지명·경로·검색어로 지목한 대상을 확정한다.
- 검색어면 `qmd query` 또는 grep 으로 후보를 찾아 `AskUserQuestion` 으로 어느 페이지인지 확정.
- 네임스페이스 확정.

### 2. 영향 분석 (read-only)
삭제 전, 파급을 먼저 수집해 보고한다.

- **백링크** — 대상을 `[[...]]` 로 가리키는 다른 페이지 목록(같은 네임스페이스와 비공개→공개 cross-link 포함).
  ```bash
  # 대상 slug 를 가리키는 페이지 찾기 (네임스페이스 루트에서)
  grep -rln "\[\[.*<대상-slug>.*\]\]" <ns>/wiki/
  ```
- **INDEX 등록 항목** — `<ns>/wiki/INDEX.md` 에 대상이 등록돼 있는지.
- **대상이 인용한 raw Sources** — 대상 페이지 하단 "Sources" 의 `raw/` 경로(삭제하지 않음, 보고만).
- **cross-link 누출 점검** — 대상이 public 인데 비공개에서 bare-slug 로 참조 중이면 함께 보고(그 참조도 끊김).

분석 결과를 표로 정리:

| 항목 | 내용 |
| --- | --- |
| 대상 페이지 | `<ns>/wiki/concepts/<이름>.md` |
| 끊기는 백링크 | N건 (페이지 목록) |
| INDEX 항목 | 있음 / 없음 |
| 인용 raw | M개 (보존 예정) |

### 3. 미리보기 + 승인
- 제거 방식과 백링크 처리를 `AskUserQuestion` 으로 확정한다.
  - **제거 방식**(매번 선택):
    - **완전 삭제** — 파일 제거. public 은 git 이력으로 복구 가능.
    - **archive 이동** — `<ns>/wiki/archive/` 로 옮기고 INDEX 에서만 내린다. 파일은 유지, 그래프에서 빠짐.
  - **백링크 처리**(끊기는 링크마다 확인):
    - **링크 제거** — 가리키던 `[[...]]` 표기를 해당 페이지에서 삭제(문장 자연스럽게 정리).
    - **다른 페이지로 대체** — 대체 대상이 있으면 `[[새-페이지]]` 로 교체.
    - **그대로 두기** — 의도적으로 끊긴 링크를 남길 때(드물게, 사용자 명시 시).
- raw 까지 지우자는 요청이면 여기서 별도 확인(기본은 보존).

### 4. 적용
승인된 내용만 실행한다.

- **완전 삭제**: 대상 파일 제거.
- **archive 이동**: `<ns>/wiki/archive/` 생성 후 이동. frontmatter 에 `archived: YYYY-MM-DD` 추가.
- **백링크 정리**: 승인된 처리(제거/대체)를 각 페이지에 적용.
- **INDEX 갱신**: `<ns>/wiki/INDEX.md` 에서 대상 항목 제거.

### 5. log append (필수)
`<ns>/wiki/log.md` **파일 맨 끝**에 추가한다 (시간순 오름차순 — 맨 위나 중간에 끼워 넣지 않는다):
```
## [YYYY-MM-DD] delete | <한 줄 요약>
- 대상: <페이지 경로> (방식: 완전 삭제 | archive)
- 정리: 백링크 N건 처리(제거 X / 대체 Y), INDEX 항목 제거
- 사유: <왜 지웠는지>
- raw: 보존(M개) | 함께 삭제(명시 승인)
```

### 6. public 이면 commit·push (별도 승인)
- public 네임스페이스 변경은 commit·push 까지 **별도 승인 절차**를 따른다(다른 brain 스킬과 동일).
- private 는 자체 repo 에 commit 한다.
- 커밋 메시지 예: `remove(<영역>): <대상> brain-delete + 백링크 정리`

## raw 원본 삭제 (예외 경로)

- 기본은 보존. 사용자가 "raw 도 지워줘", "원본까지 삭제" 처럼 명시할 때만.
- raw 삭제 시: 그 raw 를 Sources 로 쓰는 **다른 wiki 페이지가 있는지** 먼저 확인(있으면 그 페이지들의 출처가 끊김 — 경고 후 결정).
- raw 삭제도 log 에 기록.

## 외부 자원

- 대체 링크 후보 탐색에 `qmd query` 사용 가능.
- raw 파일은 위 예외 경로 외에는 절대 삭제하지 않는다.
