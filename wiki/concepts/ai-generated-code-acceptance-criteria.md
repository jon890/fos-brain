# AI 생성 코드 채택 기준

AI 코딩 도구가 만든 코드가 동작하더라도, 사람이 이해하고 유지할 수 있는 해결책인지 별도로 판단하는 기준.
핵심은 "구현 성공"과 "수용 가능한 설계"를 분리하는 것이다.

## 왜 필요한가

AI는 구현 비용을 낮추지만 리뷰와 판단 비용을 올릴 수 있다.
코드가 빠르게 생성될수록 병목은 작성 시간이 아니라 변경을 이해하고 설명하고 책임지는 시간으로 이동한다.

따라서 CI 통과, 로컬 동작, 자동 리뷰 통과만으로 수용을 결정하면 부족하다.
엔지니어가 접근 방식을 자기 언어로 설명할 수 있고, 변경 범위가 문제에 비례하며, 시스템 추론 비용을 낮추거나 최소한 늘리지 않는지 확인해야 한다.

## 거절 신호

- 접근 방식을 자기 언어로 설명할 수 없다.
- diff가 실제 문제보다 크다.
- 필요성이 증명되기 전에 새 추상화를 도입한다.
- 로컬에서는 동작하지만 시스템을 더 이해하기 어렵게 만든다.
- 자신의 이해보다 AI 산출물을 더 신뢰하게 된다.

## 운용 패턴

AI 생성 변경을 리뷰할 때는 먼저 "무엇이 바뀌었는가"보다 "왜 이 접근이 맞는가"를 설명한다.
설명이 안 되면 코드를 더 읽거나, 변경을 줄이거나, 작업을 다시 계획한다.

좋은 채택 기준은 다음 질문으로 압축된다.

- 문제에 비해 변경량이 적절한가?
- 기존 구조 안에서 해결할 수 있는데 새 레이어를 만들지는 않았는가?
- 이 코드를 다음 사람이 읽을 때 추론 비용이 줄어드는가?
- 실패했을 때 어디를 고쳐야 할지 명확한가?
- 내가 리뷰 자리에서 이 접근을 방어할 수 있는가?
