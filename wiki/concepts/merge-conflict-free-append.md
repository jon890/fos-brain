# 누적 파일의 머지 충돌을 구조로 없애기

여러 작성자(PR)가 같은 파일 끝에 append 하는 구조는 머지 충돌 자석이다.
파일 per 항목 + INDEX 라우터로 분해하면 충돌이 구조적으로 사라진다.

## 증상

- 단일 파일에 새 항목이 끝에 계속 append 되는 구조 (ADR 목록, 회피 패턴 wiki, 변경 로그 등).
- 두 PR 이 동시에 항목을 추가하면 **같은 끝줄**에서 머지 충돌이 난다.
- 항목에 번호를 매기면 카운트·인덱스 줄도 양쪽이 갱신해 추가 충돌이 생긴다.
- 단일 ADR 파일(adr.md)이 PR 마다 충돌한 실측이 출발점이다.

## 해법 — 파일 per 항목 + INDEX 라우터

- 항목 1개 = 파일 1개 (`NNN-slug.md`). 새 항목 = 새 파일이라 **본문 충돌이 0** 이다.
- INDEX 라우터(`INDEX.md`)가 번호·제목·요약 목록 + 링크를 모은다.
- 남는 충돌은 INDEX 목록 1줄뿐 — 번호·가나다순 인접 추가라 양쪽 보존으로 자동 해소한다.

## 정체성·발견성 보존 (분해의 전제)

분해하면 "잘 참조되나" 를 반드시 먼저 검토한다. 번호 기반이면 보존된다.

- **번호를 파일명에 유지** (`NNN-slug.md`) → 기존 `참조-NNN` 텍스트가 깨지지 않는다.
- **번호 glob** (`NNN-*.md`) 으로 slug 를 몰라도 파일을 찾는다.
- INDEX 가 전체 통람·라우팅을 맡아 단일 파일의 "한눈에 보기" 를 대체한다.
- AI 토큰 효율도 개선된다 — 거대 파일을 통독하지 않고 INDEX 로 필요한 항목만 읽는다.

## 검증된 구조의 이식

한 곳에서 충돌 없이 동작하는 구조 패턴을 같은 증상의 다른 곳으로 옮긴다.

- 회피 패턴 wiki(pitfalls)가 파일 per 패턴 + INDEX 로 충돌이 거의 없던 것을 관찰한다.
- 같은 구조를 ADR(adr.md)로 확장한다 — 단일 파일 → `docs/adr/NNN-slug.md` + INDEX.
- 핵심은 "검증된 구조는 증상이 같은 곳에 재사용한다" 는 이식 사고이다.
