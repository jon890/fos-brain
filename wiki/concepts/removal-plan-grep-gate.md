# 제거(removal) 작업의 grep 통과 조건 함정과 docs 부패

코드 구조물만 제거하는 작업에서 성공 기준을 "grep 결과 0건" 으로 잡으면 작업 범위 밖 텍스트 참조가 통과를 막고, 제거된 객체를 설명하던 docs 본문이 부패한다.

## grep 통과 조건이 작업 목록보다 넓을 때

- 제거 작업에서 "grep -rn 0건" 성공 기준은 작업 목록이 실제 편집하는 파일 범위와 일치해야 한다 — 더 넓으면 docstring·주석·타 phase 파일이 매치되어 통과 조건이 깨진다.
- 흔히 놓치는 잔존 참조
  - 제거 대상 심볼을 언급하는 모듈 docstring.
  - 한 phase 앞에서 다른 phase 가 지울 안내 줄을 검증하는 비대칭.
- 회피
  - grep 검증 범위를 그 phase 가 실제 편집하는 파일로 좁힌다.
  - 전역 0건 확인은 모든 제거 phase 가 끝난 뒤의 통합 검증 단계에 둔다.
  - 또는 docstring 편집을 명시 작업으로 추가한다(ruff 는 docstring 을 안 잡으므로 자동 교정이 안 된다).

## 코드 구조물 제거 시 docs 본문 부패

- class·인스턴스·엔드포인트를 제거하면 그것을 "현재 존재" 로 서술하는 docs 본문(아키텍처 요약·코드 구조 주석·엔티티 설명)이 부패한다.
- 부패 점검 대상: 아키텍처 요약 흐름도, 코드 구조 트리 주석, 엔티티 설명 bullet 등 구조물을 명명하는 모든 본문.
- 보존 대상 구분: ADR 의 시점 기록과 README 버전 히스토리(changelog)는 결정·이력의 불변 기록이므로 소급 수정하지 않는다 — 부패가 아니라 사실 기록이다.
- 예방: 변경 유형(예: "코드 구조물 제거")별로 손대야 할 docs 를 표로 못박아 설계 시점에 미리 반영한다.
