# append-only 단일 문서를 파일-per-항목 + INDEX 라우터로 분리

ADR·pitfalls 처럼 끝에 계속 항목이 누적되는 단일 markdown 문서를, 항목별 개별 파일과 INDEX 라우터 구조로 쪼개 PR 마다 반복되는 파일 끝줄 머지 충돌을 구조적으로 없애는 설계 패턴이다.

## 문제

- 단일 파일 끝에 새 항목이 append 되는 구조는 동시 작업 PR 들이 같은 끝줄 영역을 건드려 머지 충돌이 반복된다.
- 실측: 한 프로젝트의 `docs/adr.md` 에서 PR 한 건의 ADR-028 과 다른 PR 의 ADR-029 가 끝줄 충돌했다.

## 해법

- 항목마다 별도 파일(`docs/adr/NNN-slug.md`)로 분리하면 충돌 표면이 사라진다.
- 번호는 파일명에 유지해 `ADR-NNN` 참조의 정체성을 보존한다.
- 발견성은 INDEX 라우터가 보장한다.
  - 번호 glob(`NNN-*.md`)은 slug 를 몰라도 매칭된다.
  - 목록 링크로 사람이 훑는 경로도 제공한다.
- 개별 파일은 파일 자체가 주소이므로 단일 파일 시절의 intra-file 앵커(`<a id=>`)가 불필요해진다.
- 같은 file-per 패턴이 다른 디렉터리(`_shared/pitfalls/`)에서 충돌을 거의 없앤 검증된 방식이라 ADR 에도 동형으로 통일했다.

## 정합 안전망

분리가 동작을 바꾸지 않았음을 다음으로 확인한다.

- INDEX 목록 번호 집합과 개별 파일 번호 집합이 양방향 차집합 0 으로 일치한다.
- 분리 전후 헤더 수가 동일하다.
- 본문 byte 가 보존된다.

## 분리 후 brittle 지점

- 다른 브랜치가 여전히 단일 문서를 두고 같은 NNN 을 점유하면 번호 충돌이 생긴다 — 머지 전 main 의 번호와 충돌 여부를 확인한다.
