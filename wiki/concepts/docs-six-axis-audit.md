# docs-check — docs 6축 점검

docs 를 "AI 에이전트가 최소 컨텍스트로 의사결정 의도를 재구성할 수 있는 상태" 로 유지하는 점검 워크플로우.
새 프로젝트에 하네스를 깔 때 이 페이지를 seed 로 꺼내 `docs-check` 스킬을 재구성한다.

## 핵심 철학

ADR 은 "현재 유효한 기술 의사결정" 의 참고자료이지 프로젝트 역사책이 아니다.
AI 에이전트가 grep 해 능동 참조할 가치가 있으려면 문서의 대부분이 "코드만 보고는 알 수 없는 WHY" 여야 한다.
자명한 결정·마이그레이션 기록이 쌓이면 시그널 대비 노이즈가 떨어져 결국 아무도 안 읽는다.

## 검증 6축

- A 부패 — 코드가 바뀌었는데 docs 가 그대로인가. 제거된 함수·엔드포인트, 미갱신 환경변수 표, 실재하지 않는 경로.
- B 과대화 — ADR 에 코드 블록·파일 경로 나열·구현 세부·작업 내역이 누적됐는가. 최종 상태만 남기고 중간 단계는 제거한다.
- C 추론성 — "결정 / 맥락 / 대안 기각" 3축이 있는가. 맥락이 순환 설명이거나 대안 기각 근거가 없으면 미달이다.
- D 중복 — 같은 내용이 여러 docs 에 본문으로 들어갔는가. 정의는 1곳, 다른 문서는 링크·짧은 참조.
- E 자명성 (ADR 전용) — 코드·설정·git log 로 알 수 있는 결정은 ADR 로 남기지 않는다.
- F 가독성 — 마크다운 작성 규칙 위반 (semantic line break, 인라인 나열, 괄호 중첩 등).

## E 자명성 — 폐기 후보 유형

아래 유형은 코드·설정으로 자명하므로 ADR 에서 폐기 후보다.

- 라이브러리·패키지 선택 (의존성 파일로 자명)
- 폴더·디렉터리 구조 결정 (디렉터리 트리로 자명)
- 단순 마이그레이션 기록 (스키마와 git log 로 자명)
- 일반 프로그래밍 원칙 (상식)
- 환경 설정 (설정 파일로 자명)

유지 기준은 [[planning-eight-step-design]] 의 ADR 자명성 통과 조건과 같다 — 라이브러리 함정·실험 결과·대안 기각·정책·트레이드오프 중 하나에 해당해야 한다.

## 스킬 SKILL.md 의 6축 변형

스킬은 호출 시점에 컨텍스트로 로드되므로, 장황하면 토큰을 낭비하고 핵심 지시가 묻힌다.
ADR 과 다른 자명성 기준을 적용한다.

- 과대화 — 사고 사례를 길게 서술하지 말고 핵심 지시와 검증 명령, 1줄 사유로 응축한다.
- 추론성 — 지시만 있고 "왜 이 가드가 필요한지" 단서 1줄이 없으면 미래 에이전트가 가드를 우회한다.
- 중복 — 같은 가드가 여러 스킬에 반복되면 공용 `_shared/` 로 추출한다.
- 자명성 변형 — 에이전트의 일반 행동 디폴트로 추론 가능한 지시 (예: "tool 결과 확인 후 진행") 는 제거한다.

## 검증 위임 (작성과 검증 분리)

6축 점검은 read-only 검증 에이전트에 위임한다.
메인 세션은 회신을 받아 Critical 항목부터 사용자 승인 후 수정한다.
작성한 주체가 같은 맥락에서 자기 검증하지 않는다는 하네스 원칙의 연장이다.

## task 범위 검증과의 분담

| 도구 | 범위 | 시점 | 축 |
|---|---|---|---|
| docs-verifier (build-with-teams 내부) | 현재 task 변경 코드 ↔ docs | task 실행 직후 | A 부패 중심 |
| docs-check (이 워크플로) | 전체 docs ↔ 전체 코드, 품질 | 주기적·수동 | A~F 전체 |

build-with-teams 대규모 작업 완료 후, 외부 PR 머지 후, 분기별 정기로 실행하길 권장한다.

## ADR 폐기 시 결번 보존

ADR 을 폐기하면 그 번호는 결번으로 영구 보존하고 새 ADR 에 재할당하지 않는다.
외부 참조 (이슈·커밋·에이전트 메모리) 가 과거 번호를 가리킬 때 다른 결정으로 오인되는 것을 막는다.

## 추가 (2026-07-30): fos-skills 발전분

- **inline 검사 레시피를 scripts/ 로 분리**: SKILL.md 본문에 25줄짜리 셸 레시피가 여러 개 있으면 실행마다 모델이 코드를 옮겨 적어 escape 실수가 낀다. `scripts/static-check.sh` 로 분리하면서 실측 결함도 함께 잡혔다 — 코드 스팬 안 `~/path` 를 취소선 함정으로 오탐하던 문제, GNU 전용 `grep -nP` 가 BSD grep 에 없어 공용 코어에 부적합했던 문제.
- **마크다운 문법 오류 4종 자동 검출 추가**: 코드 펜스 홀수(블록 안 닫힘), 표 열 수와 헤더 불일치, 헤딩 레벨 건너뜀(h2→h4), 실재하지 않는 파일을 가리키는 상대 링크 — 렌더가 실제로 어긋나는 결정적 오류만 검출한다.
- **한국어 표기 검사를 공용 검사기에 위임**: 금지어 목록을 스크립트에 하드코딩하면 규칙 문서와 갈라진다. `~/.claude/scripts/korean-style-check.sh` 를 호출하도록 바꿔 편집 직후 hook 과 주기 감사가 같은 검사기·같은 목록을 쓰게 한다. 검사기나 규칙 파일이 없는 환경에서는 그 항목만 건너뛰고 나머지는 계속한다.
- 이 실측은 [[skill-self-scoring-two-axis]] 의 기계축(score.sh)에도 그대로 적용되는 사례다.
