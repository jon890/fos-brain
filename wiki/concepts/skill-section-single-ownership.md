# 스킬 섹션 단일 소유권 원칙

한 스킬 문서 안에서 같은 지시가 여러 섹션에 반복되면, 한 섹션만 "소유자"로 남기고 나머지는 참조로 대체한다.

## 왜 필요한가

스킬 문서는 시간이 지나며 절이 늘어난다. 새 절을 추가할 때 기존 절의 내용을 요약해 다시 적으면, 같은 규칙이 두 곳에 존재하게 된다. 한쪽만 고치면 다른 쪽이 낡은 채 남아 문서가 스스로 모순되고, 어느 쪽이 맞는지 실행 시점에 판단이 갈린다.

## 핵심 포인트

- **판정 기준**: 두 섹션이 같은 내용을 담고 있으면, 더 구체적으로 다루는 쪽(절차 섹션·하위 reference)을 소유자로 정하고, 상위 요약(핵심 원칙 등)에서는 지운다 — "통과 조건은 절차 섹션이 단일 소스"처럼 소유권을 명시하는 한 줄이 중복을 막는다.
- **자기소개·메타 설명도 대상**: "이 스킬은 공용 코어다" 같은 자기소개가 README·description·오버레이 로딩 절에 이미 있으면, 본문 첫머리의 중복 소개는 지운다.
- **끊긴 참조를 만들지 않는다**: 소유자를 옮길 때 다른 곳이 그 절 이름을 참조하고 있으면(예: "SKILL.md 규모별 완화" 같은 이름 참조), 참조를 먼저 떼거나 그 줄이 자립하도록 흡수한 뒤 지운다.
- **정렬 비교로 순수 이동 확인**: 절을 옮기거나 병합할 때 diff를 정렬 비교해 "내용은 그대로고 위치·구조만 바뀌었는지"를 확인한다.
- **다시 쓰지 않아도 되는 것도 지운다**: git 상식(브랜치에서 커밋하면 그 브랜치에 남는다), 자명한 도구 동작처럼 모델이 이미 아는 내용은 애초에 지시로 적을 값이 없다.
