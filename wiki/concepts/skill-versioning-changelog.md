# 스킬 버전+CHANGELOG 체계 (심링크 배포 전제)

여러 프로젝트가 symlink로 공유하는 스킬은 "무엇이 언제 왜 바뀌었는지" 추적할 별도 장치가 필요하다 — SKILL.md frontmatter의 `version` 필드와 스킬별 `CHANGELOG.md`로 관리한다.

## 왜 필요한가

공용 코어 스킬([[shared-skill-core-overlay]])은 한 곳을 고치면 심링크로 연결된 모든 프로젝트에 즉시 반영된다. 편리하지만 "지난주엔 이 스킬이 이런 지시였는데 왜 지금은 다르지"를 추적할 수단이 없으면, 여러 프로젝트에서 동시에 겪는 동작 변화의 원인을 알 수 없다.

## 핵심 포인트

- **버전은 배포 핀이 아니다** — 소비 방식이 symlink라 모든 프로젝트가 항상 최신 버전을 쓴다. 특정 버전에 고정할 수단이 없으므로, 버전은 "무엇이 바뀌었는지 추적하는 라벨"일 뿐 배포 관리 도구가 아니다.
- **태그를 만들지 않는다** — 배포 핀 개념이 없으니 git tag로 버전을 박제할 이유가 없다.
- **루트 CHANGELOG를 두지 않는다** — 스킬마다 갱신 시점이 다르므로 하나의 루트 CHANGELOG는 여러 스킬의 변경이 뒤섞여 갱신 지점이 갈린다. 스킬별 CHANGELOG.md로 분리한다.
- **올리는 기준 세 등급** — 지시를 제거하는 변경(minor), 단계 수·스키마가 바뀌는 변경(major), 오타·표기 교정(patch) 처럼 변경 성격에 따라 등급을 정한다.
- **측정 도구는 버전을 붙이지 않는다** — 스킬 채점 도구(`evaluation/`)는 스킬 자체가 아니라 측정 수단이므로 버전 대신 기준값 파일의 날짜로 추적한다.
