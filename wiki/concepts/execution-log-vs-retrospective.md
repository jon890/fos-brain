# 실행 산출물과 승격 지식의 수명주기

에이전트 실행 과정에서 생기는 모든 기록을 장기 지식으로 저장하지 않는다.
task, 실행 통계와 원시 회고는 전달 산출물이며, 다음 작업이 실제로 소비할 결정과 패턴만 별도 단일 소스로 승격한다.

## 이전 원칙을 바꾼 이유

이전에는 매 실행의 판정 횟수를 `RUNS.md`에 남기고 사건마다 회고 파일을 만들면 장기 추세를 볼 수 있다고 가정했다.
실제 운영에서는 이 파일을 조회하거나 다음 계획의 입력으로 쓰는 소비자가 없었다.
같은 교훈이 원시 회고와 `docs/pitfalls/`에 중복되고 완료 task까지 계속 쌓여 문서 감사 비용만 늘었다.

## 세 가지 수명

| 수명 | 예 | 보존 위치 |
| --- | --- | --- |
| 전달 산출물 | task, 실행 통계, 일회성 발견, 원시 회고 | PR·작업 보고와 Git 이력 |
| 지속 결정 | 제품 요구사항, 코드 경계, 직관에 반하는 선택 | 현재 책임 문서와 ADR |
| 재사용 패턴 | 반복 함정, 검출 방법, 회귀 방지 | [[pitfalls-file-per-pattern]], 테스트와 정적 검사 |

완료 task는 현재 코드와 ADR로 설명할 수 있으면 삭제한다.
미착수 task도 현재 제품 결정이 아니라 오래된 백로그라면 보존하지 않고, 필요해진 시점의 코드와 공식 근거로 다시 planning한다.

**「회고에 둔다」는 말의 위치를 이 페이지가 정한다.**
[[ai-harness-pattern]]과 [[work-style]], [[operations-troubleshooting]]은
일회성 사건을 회고에 둔다고 적는다. 그 회고가 어디에 남는지는 위 표가 정한다.
원시 회고는 전달 산출물이므로 PR과 작업 보고, Git 이력에 남고 wiki로 올라오지 않는다.

## 승격 조건

- 다음 작업이 실제로 읽을 소비 경로가 있다.
- 특정 사건을 넘어 재현 가능하고 일반화된다.
- 검출 방법이나 실행 조건이 구체적이다.
- 같은 내용을 소유한 기존 문서가 없거나 기존 문서를 보강한다.
- 코드로 강제할 수 있으면 문서 대신 테스트, lint와 정적 검사로 옮긴다.

실행 통계는 이름 있는 분석 소비자, 조회 주기와 자동 갱신 경로가 있을 때만 저장한다.
언젠가 쓸 수 있다는 기대만으로 수동 로그를 만들지 않는다.
