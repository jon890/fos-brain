# Codex 범용 업무 에이전트

Codex를 코드 생성기나 IDE 보조 도구로만 보지 않고, 데이터 분석, 리서치, 피드백 요약, 브라우저 조작, 협업 도구 탐색까지 맡기는 업무 에이전트 패턴.

## 핵심 관점

Codex의 가치가 커지는 지점은 "코드를 대신 쓴다"가 아니라 업무 흐름에서 필요한 도구를 연결해 반복 판단과 실행을 줄이는 데 있다.
조코딩의 OpenAI 인터뷰에서 스타트업팀은 Codex를 다음 작업에 사용한다고 설명한다.

- 스타트업 사용 데이터를 국가, 제품, 추세별로 분석한다.
- 알파 모델 피드백을 Slack과 문서에서 모아 요약한다.
- 리서치 과제를 여러 하위 agent로 나누어 병렬 수행한다.
- computer use로 브라우저와 사내 도구를 조작한다.
- Slack, Gmail, Calendar 같은 협업 표면에서 필요한 맥락을 찾는다.
- 반복 리팩터링이나 정기 점검을 자동화한다.

## 운용 패턴

업무 에이전트로 쓰려면 Codex에게 단일 코드 변경만 주는 대신, 목표, 사용할 도구, 완료 조건, 검증 방법을 함께 제공해야 한다.
이 방식은 [[ai-harness-pattern]]의 실행 계획, 완료 조건, 컨텍스트 참조와 맞닿아 있다.

좋은 요청은 다음 요소를 포함한다.

- 어떤 결과가 필요하고, 어떤 형식으로 남아야 하는가
- 어떤 자료와 도구를 확인해도 되는가
- 완료를 주장하기 전에 어떤 검증을 실행해야 하는가
- 자동화해도 되는 판단과 사람이 승인해야 하는 판단의 경계가 어디인가

## 주의점

Codex가 더 많은 도구를 연결할수록 결과 책임은 더 중요해진다.
업무 자동화가 성공해도 사람이 접근 방식을 설명할 수 없으면 [[ai-generated-code-acceptance-criteria]] 관점에서는 채택하기 어렵다.

특히 이메일, 일정, Slack, 브라우저, 파일 시스템을 다룰 때는 다음 경계를 분명히 해야 한다.

- 외부에 게시하거나 전송하는 텍스트는 미리보기를 거친다.
- 계정, 권한, 결제, production 상태에 영향을 주는 행동은 승인 경계를 둔다.
- 결과물은 검색 가능한 문서나 로그로 남겨 다음 실행의 입력이 되게 한다.
