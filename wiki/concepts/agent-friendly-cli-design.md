# 에이전트 친화 CLI 설계

사람과 AI 에이전트가 함께 쓰는 CLI 를 만들 때, 에이전트가 안정적으로 호출·파싱할 수 있도록 입력·출력·에러를 다듬는 설계 패턴.
dooray-cli 에서 정립해 nhncloud-cli 로 포팅한 재사용 패턴이다.

## 핵심 포인트

- **입력 자동 분기 (resolver)** — 같은 대상을 여러 형태로 받아 하나의 ID 로 흡수한다.
  - 예: 프로젝트를 code·내부 id·URL 어느 쪽으로 줘도 동작.
  - 매칭 공통 규칙: 정확일치 → 부분일치 → 모호하면 에러.
  - 에이전트가 입력 형태를 신경 쓰지 않고 호출할 수 있어 실패가 준다.
- **스트림 분리** — 데이터는 stdout, 에러·로그는 stderr 로 보낸다.
  - 에이전트는 stdout 만 파싱하면 되므로 로그가 결과를 오염시키지 않는다.
- **구조화 출력 모드** — 같은 명령이 용도별 출력을 제공한다.
  - `--json` — 기계 파싱용.
  - `--quiet` — 값만(스크립트 합성용).
  - 기본 — 사람용 테이블.
- **deeplink 출력** — 참조를 앱 내 이동이 가능한 표준 URI 로 출력한다(예: `dooray://.../tasks/{id}`).
- **일관된 종료코드** — 단일 에러 타입(예: `DoorayCliError(message, exitCode)`)으로 exit code 를 통일해, 에이전트가 성공·실패를 코드로 판단한다.
- **resolve 캐시** — 이름→ID 같은 반복 조회를 TTL 캐시로 줄인다.

## 왜 중요한가

- 에이전트는 사람과 달리 "대충 보고 이해"하지 못한다. 출력이 섞이거나 입력 형태가 까다로우면 바로 실패한다.
- 이 패턴을 지키면 같은 CLI 를 사람은 편하게, 에이전트는 안정적으로 쓴다 — 하나의 도구로 두 사용자를 만족시킨다.
