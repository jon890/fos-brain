# ADR-012: Quartz는 수정하지 않는 업스트림 원본으로 두고 자체 코드를 분리한다

- 상태: 채택
- 날짜: 2026-09-04

## 맥락

`quartz/`는 최초 커밋에 업스트림을 복사해 넣은 것이라 공통 조상이 없다.
업스트림을 따라가려면 병합할 기준점이 없어 손으로 파일을 비교해야 한다.

실측으로 복사 시점은 업스트림 커밋 `d25a6ea`이고, 그 시점과 비교한 실제 수정은 업스트림 파일 8개에 313줄이다.
이 중 셋은 업스트림이 사용자 편집을 전제한 설정 파일이라 문제가 아니다.
나머지는 커스텀 컴포넌트를 재수출 목록에 등록하고, 콘텐츠 색인에 지식 metadata를 더하고,
페이지 렌더 함수에 문서 상단 항해 요소를 직접 넣고, 문서별 그래프의 색과 범례를 바꾼 것이다.

한편 자체 구현 코드는 테스트를 빼고 6,309줄로, 실제로 사용하는 Quartz 코드와 규모가 비슷해졌다.
Quartz를 계속 쓸지 자체 구현으로 갈지는 아직 정하지 않았으나,
어느 쪽으로 가든 업스트림 표면과 자체 코드가 섞여 있으면 판단할 근거를 만들 수 없다.

## 결정

- 업스트림 파일을 수정하지 않는다. 자체 코드는 `quartz/quartz/**` 밖의 별도 디렉터리에 둔다.
- 업스트림을 `quartz-upstream` remote로 연결하고 복사 시점 커밋을 공통 조상으로 삼아 병합할 수 있게 한다.
- 커스텀 컴포넌트와 emitter를 업스트림 재수출 목록에 등록하지 않고 설정 파일이 경로로 직접 불러온다.
- 화면에 얹는 요소는 페이지 렌더 함수를 고치지 않고 layout의 컴포넌트 자리로 넣는다.
- Memory Atlas가 쓰는 확장 색인은 업스트림 콘텐츠 색인을 고치지 않고 커스텀 emitter가 자체 파일로 내보낸다.
- 문서별 그래프 수정은 업스트림 상태로 되돌린다. 본문 페이지에서 사용하지 않으므로 화면이 달라지지 않는다.

이 경계가 유지되면 Quartz에 의존하는 표면이 색인 파일과 layout 둘로 좁아진다.
자체 구현으로 갈지는 그 표면을 보고 따로 판단한다. 이 결정은 그 판단을 앞당기지도 막지도 않는다.

## 검토한 대안

- 지금 Quartz를 제거하고 자체 정적 생성기를 만드는 방식은, 제거할 표면이 코드 곳곳에 흩어져 있어 교체 범위를 모른 채 시작하게 된다.
  Obsidian 문법 변환과 링크 해석은 실제로 다시 만들어야 하는 코드이며, 이 경계를 먼저 그으면 그 범위를 수치로 확인할 수 있다.
- 업스트림 v5로 먼저 올라가는 방식은 v5가 플러그인을 별도 패키지로 분리한 major라 이번 정리와 이전 작업이 한 변경에 섞인다.
- 지금처럼 두고 필요할 때만 손으로 비교하는 방식은 수정 지점이 늘어날수록 비용이 커지고, 어디가 내 코드인지 판단하는 일이 매번 반복된다.
