# ADR-008: 기본 탐색은 2D 혼합 관계 지도와 선택 중심 지역 관계를 사용한다

- 상태: 채택
- 날짜: 2026-09-02

## 맥락

[ADR-002](002-memory-atlas-3d-home.md)는 전체 지식을 조망하는 3D Memory Atlas를 홈에 도입했다.
3D는 전체 지형을 보는 데는 효과적이지만 깊이와 카메라 거리가 선택 노드의 여러 hop 관계를 한눈에 비교하기 어렵게 만든다.
기존 별자리 배치는 첫 tag와 slug hash를 사용하므로 의미가 비슷한 문서를 가깝게 둔다는 계약도 없다.

Memory Atlas는 public과 private 콘텐츠를 서로 다른 빌드로 다룬다.
private 문서에서 계산한 제목, tag, 군집 이름과 의미 관계가 public 정적 산출물에 남지 않아야 한다.
Quartz는 Preact 서버 렌더와 SPA 전환을 이미 사용하므로 관계 탐색을 추가하면서 별도 React 앱과 상태 계층을 함께 도입할 이유도 없다.

## 결정

- 홈은 2D 전체 관계 지도를 기본으로 열고 기존 3D는 선택 가능한 조망 모드로 유지한다.
- 전체 배치는 실제 wiki link를 가장 강한 신호로 사용하고, 공통 tag, qmd vector 유사성 순서로 계수를 낮춰 합친다.
- 노드를 선택하면 실제 wiki link의 최단 hop depth를 계산해 선택 노드 중심으로 다시 배치한다.
  전체 노드는 원래 2D 좌표에 옅게 남기고 depth가 깊어질수록 관계를 옅게 표시한다.
- 커리어, 건강과 AI를 고정 시작점으로 두고 RAG를 AI 아래의 현재 집중 항목으로 표시한다.
  자동 시작점은 현재 혼합 graph에서 계산하되 wiki와 정적 의미 관계 파일에 저장하지 않는다.
- qmd 의미 관계는 내부 HTTP 검색으로 빌드 전에 생성한다.
  생성 파일에는 slug 쌍과 점수만 담고, Quartz가 현재 빌드의 slug로 다시 제한한 결과만 게시한다.
  생성 파일이 없거나 잘못되면 wiki link와 tag만 사용한다.
- 기존 Preact를 유지하고 React나 client hydration 계층을 추가하지 않는다.
  Preact는 역할이 작은 서버 렌더 컴포넌트를 조합하고, 브라우저 controller는 최소 사용자 상태만 보관한다.
  graph 계산은 DOM에 의존하지 않는 TypeScript로 분리하고 2D와 3D 렌더러는 같은 제거 가능한 생명주기 계약을 구현한다.
- 브라우저 회귀는 `browser-driver`만 사용한다.
  Orca에서 상호작용과 worktree 경계를 판정하고, 비활성 탭이라 `shot`만 실패하면 상호작용 판정과 분리해 headless backend로 화면 증거를 만든다.
  headless 결과로 Orca 상호작용 실패를 성공 처리하지 않는다.
- 현재 driver에는 실제 key 입력 명령이 없으므로 접근성 검사는 native `button`, tab order와 key handler를 확인한다.
  synthetic key event와 `.click()`은 별도 단계로 실행해 실제 키 입력으로 오인하지 않는다.

## 검토한 대안

- 3D 카메라를 선택 노드에 더 가까이 이동하는 방식은 여러 hop을 같은 평면에서 비교하기 어렵고 전체 위치와 지역 관계를 동시에 보여주지 못해 채택하지 않았다.
- tag만으로 군집을 만드는 방식은 표현이 다른 관련 문서를 놓치고 첫 tag 품질에 지나치게 의존해 채택하지 않았다.
- 브라우저가 qmd를 직접 호출하는 방식은 내부 검색 경계를 외부에 노출하고 정적 배포를 깨므로 채택하지 않았다.
- 계산한 의미 관계와 자동 시작점을 wiki에 저장하는 방식은 원래 지식과 일시적인 모델 계산을 섞고 모델 변경 때 대량 수정을 만들므로 채택하지 않았다.
- React 앱이나 새 graph 라이브러리를 도입하는 방식은 기존 Preact, D3와 TypeScript로 해결할 수 있는 범위에 중복 상태와 의존성을 추가하므로 채택하지 않았다.
