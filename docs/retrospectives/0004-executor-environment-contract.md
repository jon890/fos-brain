# 검증에서 HOME을 임시 경로로 바꿔 환경 계약을 어김

## 관찰

Phase 2 리뷰 수정 실행자가 고정 qmd wrapper 부재를 흉내 내려고 `HOME`을 임시 경로로 바꿨다.
저장소 파일은 바뀌지 않았지만 mise가 임시 경로에 Node를 설치했다.

## 원인

실패 경로를 빠르게 확인하려다 공용 시스템 선택값을 재사용하지 말라는 실행 규칙을 놓쳤다.

## 영향

검증이 실제 사용자 환경과 다른 런타임 초기화 동작을 일으켰다.
이번에는 저장소 변경이 없었지만 같은 방식은 민감한 설정 경로나 넓은 삭제 대상을 잘못 가리킬 수 있다.

## 대응

결과는 실제 고정 wrapper가 있는 환경에서 team-lead가 다시 검증했다.
실패 경로 검증은 코드의 명시적 진단 분기와 정적 잔재 검사로 대체했다.

## 검증

실제 setup-check와 검색 벤치마크가 고정 wrapper를 사용해 성공했다.
두 스크립트에서 PATH fallback과 자동 설치 문자열이 사라졌음을 확인했다.

## 배운 점

부재 상황을 흉내 낼 때도 `HOME`, `CODEX_HOME` 같은 공용 선택값을 바꾸지 않는다.
검증 가능성을 위해 제품 코드에 테스트 전용 환경 우회를 추가하지 않고 정적 검사와 실제 경로 검사를 조합한다.

## 후속

기존 AGENTS.md에 같은 금지 규칙이 있어 추가 승격은 하지 않는다.
