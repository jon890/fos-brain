# 경계 검사가 부재한 파일을 건너뛴다

## 증상

검사 대상을 실제 파일 목록에서 뽑고 `[[ -f "$path" ]] || continue` 로 없는 것을 넘기면,
파일이 사라진 상태가 위반이 아니라 통과가 된다.
검사가 잡으려던 것이 "바뀌지 않았는가" 인데 실제로 잡는 것은 "있는 것 중에 바뀐 것" 이라,
지워버리면 통과한다.

## 실제 사례

`quartz/scripts/verify-upstream-untouched.sh` 의 루트 파일 비교가 이 형태였다.
같은 스크립트의 `quartz/` 트리 비교는 기준 커밋의 파일 목록을 돌며 부재를 `삭제:` 로 잡는데,
루트 비교만 저장소의 현재 파일을 기준으로 삼아 비대칭이었다.
`tsconfig.json` 을 지워도 경계 검사가 종료 코드 0 을 냈다.

## 고치는 방법

검사 대상 목록을 검사받는 쪽이 아니라 검사하는 쪽이 소유한다.
`ROOT_FILES` 처럼 스크립트에 목록을 명시하고, 목록에 있는데 파일이 없으면 위반으로 잡는다.
목록에서 뺀 항목은 왜 뺐는지 주석으로 남긴다.

## 검출

```bash
rg -n '\[\[ ! -f|\[\[ -f .* \]\] \|\| continue' --glob '*.sh'
```

걸린 자리마다 검사 대상 목록이 어디서 오는지 본다.
현재 파일 시스템에서 오면 부재가 검사에서 빠진다.
