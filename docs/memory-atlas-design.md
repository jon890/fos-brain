# Memory Atlas 디자인

## 화면의 한 가지 역할

Memory Atlas는 개인 지식 전체에서 현재 생각과 다음에 읽을 문서를 찾는 홈 화면이다.
문서 작성이나 장식용 통계보다 관계 탐색을 먼저 보여준다.

## 시각 정체성: 심해 항해도

fos-brain의 청록색과 테라코타색을 어두운 해도 위의 신호색으로 다시 해석한다.
검정 배경과 형광색을 쓰는 일반적인 AI 그래프 대신, 오래 축적한 지식을 탐사하는 개인 관측실처럼 보이게 한다.

| 토큰 | 값 | 역할 |
| --- | --- | --- |
| `atlas-abyss` | `#030b11` | 화면 전체의 심해 배경 |
| `atlas-trench` | `#07171d` | 필터, 상세 패널, 문서 표면 |
| `atlas-current` | `#5cc8b2` | concept와 주요 동작 |
| `atlas-ember` | `#e99368` | topic과 확인 필요 상태 |
| `atlas-pearl` | `#e8e3d4` | 제목과 선택 정보 |
| `atlas-sounding` | `#6e8790` | 보조 문구와 비활성 연결 |

제목은 `Gowun Batang`, 본문과 조작은 `IBM Plex Sans KR`, 수치와 상태는 `IBM Plex Mono`를 사용한다.
긴 본문도 같은 어두운 항해도 셸에서 읽되, 그래프와 달리 폭을 제한한 읽기 열과 밝은 본문 대비를 사용한다.

## 구조

```text
┌──────────────────────────────────────────────────────────┐
│ [FOS / MEMORY · 상태]   [2D 관계|3D 조망] [검색] [Brain에게 묻기] │
│ ┌──── 탐색 오버레이 ────┐                               │
│ │ 시작점                  │       전체 2D 관계 지도       │
│ │ 커리어 건강 AI          │     또는 선택 중심 지역 관계   │
│ │   현재 집중: RAG        │                               │
│ │ 발견한 영역             │   [전체 지도로 · 중심 · depth] │
│ │ 렌즈와 태그             │                               │
│ └────────────────────────┘                 [선택 상세]    │
│                  [Brain 답변 · 근거 문서]                 │
└──────────────────────────────────────────────────────────┘
```

그래프는 화면 전체를 채운 고정 배경이며 메뉴와 상세는 그 위에 겹쳐 열린다.
데스크톱 탐색 메뉴는 약 260px 안에서 chip과 접히는 섹션을 사용한다.
시작점은 filter보다 먼저 보여 사용자가 검색어 없이도 탐색을 시작할 수 있게 한다.
커리어, 건강과 AI는 같은 위계로 두고 RAG는 AI 아래의 `현재 집중`으로 한 단계 들여쓴다.
자동으로 찾은 시작점은 `발견한 영역`으로 분리해 사용자가 고정 개인 영역과 계산 결과를 혼동하지 않게 한다.
문서 결과는 기본 화면을 차지하지 않고 검색어가 있을 때 메뉴 안에서만 나타난다.
390px 화면에서는 모드 전환, 작은 필터 버튼과 검색 막대만 남기고, 시작점과 filter는 왼쪽 서랍으로, 상세는 아래 시트로 연다.
질문 패널은 데스크톱에서 그래프가 보이는 하단 오버레이로, 모바일에서 아래 시트로 연다.

화면과 canvas는 각각 남은 너비를 다시 계산하지 않는다.
두 요소는 같은 viewport 경계를 사용하며 1440px와 390px에서 보이는 요소의 오른쪽 경계가 viewport를 넘지 않아야 한다.

## 기억의 항적

2D 전체 지도는 실제 wiki link를 단단한 항로로, 계산한 의미 관계를 더 가늘고 옅은 해류로 표현한다.
전체 지도에서 의미가 비슷한 문서가 같은 해역에 모이지만 두 관계의 선 모양은 구분한다.

노드를 선택하면 선택 노드를 중앙에 두고 실제 wiki 연결을 동심 depth에 다시 배치한다.
1-hop은 가장 밝게, 다음 hop은 단계적으로 옅게 표시한다.
선택 관계에 포함되지 않은 전체 노드는 원래 전체 지도 위치에 낮은 불투명도로 남긴다.
연결 노드를 선택하면 해당 노드를 새 중심으로 같은 계산을 반복한다.

3D에서 노드를 선택하면 직접 연결된 경로만 민트색과 점토색으로 밝아지고 나머지는 해도 뒤로 가라앉는다.
선택 노드에는 한 번 퍼지는 수중 음파와 얇은 궤도를 표시해 현재 관찰 지점을 알린다.
이 음파가 화면에서 사용하는 유일한 강한 움직임이다.

사용자가 움직임 줄이기를 선택하면 궤도 회전과 자동 카메라 이동을 끈다.
필터와 패널은 180ms 안에서 상태만 전환하며 장식용 입자와 반복되는 등장 애니메이션은 사용하지 않는다.

## 조작과 상태

- 홈은 2D 관계 지도로 시작하고 상단의 `3D 조망`으로 기존 별자리를 열 수 있다.
- 2D 노드는 제목을 가진 HTML 버튼이며 click, `Enter`와 `Space`로 선택한다.
- 2D 노드 선택은 상세 패널을 열고 중앙의 지역 관계를 다시 계산한다.
- `전체 지도로`는 선택을 해제하고 처음의 결정적 좌표를 복원한다.
- 3D에서 드래그는 카메라 회전, 휠과 두 손가락 동작은 확대와 축소를 담당한다.
- 3D 노드 선택은 상세 패널을 열고 직접 연결된 기억의 항적을 강조한다.
- 검색과 필터는 그래프, 노드 수, 결과 목록에 같은 결과를 적용한다.
- filter 결과에서 선택 노드가 사라지면 전체 지도로 돌아간다.
- qmd 의미 관계를 사용할 수 없으면 상태 문구로 알리고 wiki link와 tag 관계만 사용한다.
- 결과가 없으면 선택 조건을 유지한 채 초기화 동작을 보여준다.
- 현재 모드 초기화가 실패하면 다른 모드와 검색 가능한 문서 목록을 남기고 다시 시도할 수 있게 한다.
- 그래프 조작을 못 하는 사용자도 검색 결과와 상세 패널만으로 원문에 이동할 수 있다.
- 원문은 같은 어두운 항해도 셸에서 열리고, 항해도로 돌아가는 동작이 항상 보인다.
- 문서에서 돌아오면 선택했던 노드와 카메라 상태를 복원한다.
- 제목·태그 검색과 자연어 질문은 다른 입력으로 유지해 현재 그래프 필터를 예측 가능하게 만든다.
- 질문 중에는 검색, 근거 읽기, 답변 생성 상태를 구분해 보여준다.
- 답변은 모델이 만든 HTML을 렌더하지 않고 평문으로 표시한다.
- 출처는 public과 private 표시, 짧은 발췌문과 원문 이동 동작을 함께 제공한다.
- 질문 패널이 열려 있을 때만 출처 노드를 별도 신호색으로 강조하고 닫으면 기존 선택 강조 상태로 돌아간다.
- 근거가 없으면 일반 지식을 섞지 않고 brain에 관련 지식이 없다는 빈 상태를 보여준다.
- 질문과 답변을 저장하지 않는다는 설명을 입력 가까이에 둔다.

## 프론트엔드 구성 원칙

Memory Atlas의 HTML 구조는 기존 Preact를 사용하고 React 의존성을 추가하지 않는다.
화면 조각은 모드 전환, 시작점, 관계 문맥, filter와 상세처럼 한 가지 역할을 가진 typed props 컴포넌트로 나눈다.

브라우저 상태에는 사용자가 바꾸는 모드, 선택 slug와 filter만 둔다.
선택 노드 객체, depth, 강조 목록, 좌표와 시작점은 기존 상태에서 계산하며 중복 저장하지 않는다.
그래프 계산은 DOM 없이 검사할 수 있는 TypeScript 모듈이 맡고, 2D와 3D 렌더러는 같은 생성·갱신·제거 계약 뒤에 둔다.
사용자 event는 handler에서 처리하며 SPA 이동, 모드 전환과 제거 시 renderer와 listener를 정리한다.

## 의도적으로 복제하지 않는 요소

참고 화면의 검정과 버건디 색상, 언어 전환, 로그인 유도 문구는 복제하지 않는다.
외부 인증 계층이 접근 제어를 담당하므로 홈은 지식 탐색만 설명한다.
현재 wiki에 근거가 없는 주장 유형과 의미 연결 필터도 만들지 않는다.

처음 검토한 종이색 배경과 테라코타 중심 안은 최근 생성형 UI에서 반복되는 형태라 제외했다.
종이색은 선택 정보에만 제한하고, 심해 청록색 공간과 기억의 항적을 fos-brain의 고유 요소로 사용한다.

## 반복 검증

Memory Atlas 회귀 검사는 `cd quartz && scripts/verify-memory-atlas.sh` 한 명령으로 실행한다.
실행기는 서식 검사, 타입 검사, 단위 검사, 실제 Quartz 빌드, 임시 서버 기동, 브라우저 회귀 검사를 순서대로 수행하고 서버를 정리한다.

브라우저 검사는 다음 경계를 고정한다.

- 1440×1000과 390×844 화면에서 보이는 요소와 문서 본문에 가로 넘침이 없다.
- WebGL canvas가 viewport를 채우고 빈 화면이 아니며, 움직임 줄이기 환경에서도 탐색할 수 있다.
- 검색, 유형 필터, 초기화, 상세 패널, 모바일 서랍, 키보드 초점 이동이 동작한다.
- 원문으로 이동한 뒤 선택과 카메라 상태를 복원하고, 선택 해제 뒤에는 이전 선택이 되살아나지 않는다.
- 홈은 서버 렌더 단계부터 항해도 셸을 사용하고, 문서에는 기존 그래프나 Memory Atlas 런타임이 중복되지 않는다.
- 콘텐츠 색인 요청이 실패하면 검색 가능한 대체 목록과 다시 시도 동작을 제공한다.
- 질문의 입력 제한, 처리 중 중복 제출, 빈 근거, qmd 오류, 모델 API 오류와 시간 초과를 각각 재현한다.
- 답변의 HTML 문자열이 실행되지 않고 평문으로 보이는지 검사한다.
- 답변 출처를 누르면 올바른 public 또는 `/_private/` 문서로 이동하는지 검사한다.
- 질문 패널을 닫거나 다른 그래프 노드를 선택하면 이전 출처 강조가 남지 않는지 검사한다.
- 1440px와 390px에서 질문 패널, 키보드와 오류 문구가 viewport를 벗어나지 않는지 검사한다.

기본 검증 포트는 HTTP `8096`, 실시간 갱신 `3096`이다.
충돌할 때는 `MEMORY_ATLAS_VERIFY_PORT`와 `MEMORY_ATLAS_VERIFY_WS_PORT`로 바꾼다.
Quartz 로그, 브라우저 assertion과 화면 캡처는 기본적으로 `/tmp/fos-brain-memory-atlas-suite`에 남긴다.
브라우저 연결 시간 초과만 새 격리 세션으로 복구하며, 제품 동작이나 화면 assertion 실패는 재시도하지 않고 즉시 실패로 기록한다.
